### Complete 40-Task Catalog (Rewritten for Beginners)

#### 1. Appointment list + book form

* **Step 1:** Create an appointment blueprint (name, time) and set up the outer container component.
* **Step 2:** Store appointments in app memory; show rows if booked, or a "No appointments scheduled today" note if empty.
* **Step 3:** Connect the booking input boxes directly to memory so names and times are tracked as you type.
* **Step 4:** Stop the form from refreshing the page on click, append the new appointment to the list, and wipe the inputs clean.

#### 2. Appointments API with slot conflicts

* **Step 1:** Create an in-memory storage drawer and an ID generator to give each booking a unique receipt number.
* **Step 2:** Check incoming requests for missing patient names or times, rejecting incomplete data with an error (400).
* **Step 3:** Scan existing appointments to confirm no other booking already occupies that exact time slot.
* **Step 4:** Provide a GET doorway to read bookings and a POST doorway that blocks overlapping times with a conflict error (409).

#### 3. Day board: filter appointments by provider

* **Step 1:** Define the appointment blueprint (including the provider name) and set up the day-board screen layout.
* **Step 2:** View appointments through a provider filter lens, displaying only their patients or a "No visits for this provider" message.
* **Step 3:** Connect input text boxes to memory so newly entered appointment details are tracked live.
* **Step 4:** Intercept submission, add the new visit to memory, clear the form, and let the provider filter sort it.

#### 4. Deposit list + take-deposit form

* **Step 1:** Design a blueprint for a deposit record (customer, amount) and build the shell container.
* **Step 2:** Hold deposits in memory; show a transaction row for each payment, or an "All deposits clear" message when empty.
* **Step 3:** Wire payment amount and customer fields to memory so keystrokes register in real time.
* **Step 4:** Block the default page reload, drop the new deposit into the ledger, and clear the input boxes.

#### 5. Deposits API with held/applied status

* **Step 1:** Set up an in-memory ledger and an ID helper to stamp each payment with a distinct ID.
* **Step 2:** Validate that incoming deposits include an amount greater than zero and a valid customer reference.
* **Step 3:** Let the server determine whether the deposit is "held" or "applied" based on balance rules rather than client input.
* **Step 4:** Set up a GET route to list deposits and a POST route that attaches the server-verified status on save.

#### 6. Coverage API with open/filled status

* **Step 1:** Set up a shift-coverage memory drawer and an ID generator for unique coverage tickets.
* **Step 2:** Check that coverage requests include a shift date, role, and department before proceeding.
* **Step 3:** Have the server assign "open" if no worker is attached or "filled" once an employee is assigned.
* **Step 4:** Build endpoints to fetch all coverage tickets (GET) and register new requests with their calculated status (POST).

#### 7. Open coverage list + request form

* **Step 3:** Connect input boxes to state so requested roles and shift hours are tracked character-by-character.
* **Step 4:** Prevent form submission refresh, append the shift request to the list, and empty the inputs.

#### 8. Inventory master table

* **Step 1:** Create an item blueprint describing an inventory product (SKU, name, stock count, cost).
* **Step 2:** Set up a storage container in state to hold the incoming catalog.
* **Step 3:** Fetch the real inventory catalog from the API when the component first appears on screen.
* **Step 4:** Configure the spreadsheet columns using TanStack Table to map headers to data fields.
* **Step 5:** Draw table headers and data rows, displaying a loading message while fetching and an empty state if no stock exists.

#### 9. Purchase order form & receive modal

* **Step 1:** Define blueprints for vendors, items, and line items, then create the purchase order screen layout.

* **Step 3:** Fetch active vendors and item catalogs from the server on initial load.
* **Step 4:** Submit the completed order to the server using a POST call, creating an official pending purchase order.
* **Step 5:** Send a receive confirmation call to the server to mark items arrived and immediately reflect updated warehouse counts.
